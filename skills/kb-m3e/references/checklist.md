# M3E strict-mode compliance checklist

The critic runs this list against a mockup (HTML/CSS, image, Figma export) or code (QML, Compose, web). Each item says what to inspect and what counts as off-spec. A finding cites the item number and the reference file and section that defines the value. A value is compliant when it equals the reference value or sits on a line marked `Room for choice:` and stays inside what that line allows; a choice also needs to be recorded (design notes or code comment), so the next reviewer can tell intent from drift.

Item style: `**Rule.** Why. Check: how to verify`.

## 1. Tokens, not literals

1. **Every colour is a role.** Raw colours break dynamic colour, dark theme and contrast levels. Check: list every colour in the artefact; each maps to a role (`color.md`). Hex/rgba literals outside the generated scheme or theme singleton are off-spec; so is an alpha other than a state-layer or disabled opacity.
2. **Every radius is on the scale.** Check: each corner is 0, 4, 8, 12, 16, 20, 28, 32, 48, full, a component inner-corner value, 50% where an entry says so, or an optical-roundness result (outer − padding). Anything else is off-spec (`shape.md`).
3. **Every text style is one of the 30 styles.** Check: size, line height, tracking and weight match one row in `type.md`; no in-between sizes; emphasized only where `type.md` allows it.
4. **Every spring or curve is a motion token.** Check: springs are one of the six `md.sys.motion.spring.*` in the declared scheme; curves and durations match the fallback table or legacy transition tokens (`motion.md`). Literal damping/stiffness or ad-hoc `Easing.OutCubic` style curves are off-spec.
5. **Every elevation is a level.** Check: shadow levels 0–5 at 0/1/3/6/8/12; resting level matches the component (`layout.md` elevation list). Tinted surfaces for elevation are off-spec.
6. **Spacing follows the component tables and layout margins.** Check: component paddings and gaps equal `components.md`; window margins 16 (compact) or 24; pane spacers 24; fixed panes 360/412.

## 2. Components

7. **Each component is an M3E variant, not a baseline one the spec marks "not recommended".** Check: no 80dp navigation bar, no baseline navigation rail, no small FAB, no baseline extended FAB, no bottom app bar, no surface FAB, no 24dp-padded small button in new work.
8. **Sizes match the component table.** Check: heights, widths, icon sizes, paddings per size row in `components.md`; a 48dp button or a 36dp icon button is off-spec.
9. **Colours match the component's style and state.** Check: default, hover, focus, pressed, selected, disabled colours per entry; state layer colour equals content colour; disabled content on-surface 0.38, containers on-surface 0.10.
10. **Shapes and morphs match.** Check: resting, pressed and selected shapes per entry; morphs only where `shape.md` lists them; no press morph on cards, chips, dialogs, nav items.
11. **Usage limits hold.** Check: one FAB or extended FAB per screen; one filled button per view as the guidance; dialogs ≤ 2 actions; nav bar 3–5 destinations, collapsed rail 3–7; FAB menu ≤ 6 items; toolbar never with a nav bar; chip sets all single- or all multi-select; switches for binary options only.
12. **Labels follow the content rules.** Check: button labels 1–3 words, sentence case, single line, untruncated; extended FAB 1–2 words; search placeholder contains "Search"; dialog headline is not a bare "Are you sure?".

## 3. Motion (mandatory)

13. **Every state change animates.** Check: for each component, the `Motion:` line in `components.md` is implemented; a state that snaps without reduced motion on is off-spec.
14. **Right spring type.** Check: colour and opacity on effects springs (no overshoot); position, size, rotation and corners on spatial springs.
15. **Right spring speed.** Check: components on fast, partial-screen surfaces (sheets, expanded rail, search view collapse) on default, full-screen on slow; exceptions only as listed per component.
16. **Transitions are simple.** Check: page transitions use the legacy easing tokens and one of the five patterns; no bouncy overshoot on navigation; top-level destinations fade; no long cross-fades.
17. **Reduced motion is honoured.** Check: with the platform setting (or app animation speed "none") on, slides become fades, morphs and parallax stop, end states still render.

## 4. Colour system

18. **Pairs are used as intended.** Check: on-X on X; container roles never used for text; inverse roles only on components that name them.
19. **Scheme generated by MCU with a recorded variant and contrast level.** Check: generator, source, variant (tonal spot by default) and contrast are stated; light on-container roles use tone 30.
20. **Contrast.** Check: text ≥ 4.5:1 at standard contrast; icons and non-text indicators ≥ 3:1; progress tracks under 3:1 carry a stop indicator.

## 5. Layout and input

21. **Breakpoint behaviour.** Check: navigation and pane count per `layout.md` at 600/840/1200/1600; swaps are functionally equivalent; colour roles and reading order do not change across sizes.
22. **Targets ≥ 48×48.** Check: every interactive element, including XS buttons, chips' secondary actions, switches, dense variants.
23. **Desktop pointer and keyboard.** Check: hover state on actionable components only; right cursor shapes; secondary click opens a context menu and never the primary action; visible 3dp secondary focus ring on Tab; wheel scrolls the area under the cursor.
24. **Density only by opt-in.** Check: no default dense variant; text size unchanged in dense; density not tied to breakpoint.

## 6. Choices and deviations

25. **Each decision sits on a `Room for choice:` line.** Check: for every value that differs from a fixed default, find the line that permits it; if none exists, it is off-spec.
26. **Deviations are documented decisions.** Check: a pattern from "Deliberate desktop deviations" in `layout.md` is accepted only when the project's own docs record that decision; otherwise flag it.

## Reporting format

```markdown
### M3E strict review
- [off-spec] 8 Button size: "Save" is 48dp high; S is 40, M is 56 (components.md, Button)
- [off-spec] 14 Spring type: card hover colour uses fast.spatial; colour needs an effects spring (motion.md, Schemes and spring tokens)
- [choice, recorded] Toolbar vibrant colour (components.md, Toolbar, Room for choice)
- [choice, unrecorded] List segmented style used without a note (components.md, List)
- Not checked: <item>, because <reason>
```
