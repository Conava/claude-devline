# Agent process checklist

Selected for every task, for implementers and reviewers alike: how an agent establishes facts, keeps its scope, recovers from failure and hands work over. The other checklists say what to verify in the code; this one says how to work so the verification means something. Reviewers apply it to the agent's report and diff, not only to the code.

## Ground every claim

- **Check every claim against the primary source, not a summary of it.** Plans, review comments, code comments, memory and your own recollection of a file read an hour ago are often wrong or stale; a restated secondary source is the most common defect in long agent runs. Check: each factual claim in a report, plan, PR body or code comment names what was read or run to establish it (the library source, the installed package, a live run, a count you made yourself); a claim taken from a plan or review is re-checked before anything is built on it, including a dismissal of a finding as "known" or "out of scope".
- **Check every API against the installed or released version.** Models reach for deprecated or invented signatures, and a dependency can move a major version between plan and implementation. Check: for each library call new to the codebase, the signature was read in the lockfile version's source or docs (`node_modules/<pkg>/package.json` and its type declarations, `pip show -f`, `go doc <pkg>.<Sym>`, `cargo doc`, the sources jar); the compiler or linter shows no deprecation warning in changed lines; after a major upgrade, renamed config keys still bind (log or actuator output) and moved test annotations still run (test counts unchanged).
- **Prove a check can fail before trusting its pass.** Linters with warnings suppressed, probes that load the wrong copy of a package, detectors that never ran, filtered `diff` output and zsh globs that match nothing all print a clean result for broken input. Check: plant one known error and see the linter, scan or detector fail; confirm instrumentation executed before trusting a null result; compare files with `cmp -s` or `diff -q` and read the exit code; treat "0 results", "0 passed, 0 failed" and "all skipped" as "did not run" until shown otherwise.
- **Self-review counts only with tool or test evidence.** Rereading your own code without an external signal does not reliably find defects and can make the code worse; execution, analyser and test feedback measurably does. Check: every "reviewed", "double-checked" or "fixed" statement in a report names the command, test, analyser output or diff hunk that showed the defect and its absence afterwards.
- **Re-read the requirements from the source before declaring done.** Long sessions lose detail from early in the context, and requirements given over several turns drift. Check: the acceptance criteria are ticked against the issue or spec text re-opened at verification time, quoted or linked, not against the session's memory of them.
- **Name doubt instead of papering over it.** A silent workaround for an unclear build failure, convention or domain rule hides the problem and often guesses wrong. Check: the report lists every unresolved doubt and every assumption made; a visible defect outside the task is reported (with an offer to fix it if small), not fixed silently or ignored.

## Keep the change to what was asked

- **Keep the diff to the task.** Rejected agent pull requests are larger and are turned down for unwanted features and duplicates, and vulnerability risk grows with patch size. Check: `git diff --stat <base>` lists only files the task needs; every hunk maps to a requirement; refactors, renames and "while I was here" edits are split out or listed as deliberate extras; where the request reads two ways, the report says which reading was built and why.
- **Reuse what exists before writing something new.** Agent changes add more near-duplicate code than human ones and reviewers rarely notice; a second copy of a helper or a hand-spelled list drifts from the first. Check: before adding a helper, component, utility class or constant list, `grep -rn` (or `git grep`) for its purpose and key calls; the report names what was reused or why nothing fit; a list that must mirror another imports it or has a test that fails when they drift.
- **Definition of done includes deleting the old path and updating the docs.** A replacement that keeps the old code doubles maintenance, and stale names linger in comments, READMEs and config. Check: the change deletes the code it replaces; `git grep -n '<removed name>'` across code, comments and docs returns nothing; the README, settings docs and changelog describe the new behaviour.
- **Never hand-edit generated files or synced catalogs.** The generator or sync overwrites the edit or turns it into a conflict, and a stale generated file fails CI. Check: every generated file in the diff was produced by the project's generator command, run in this session; translation catalogs synced from an external service are untouched.
- **Keep local and process references out of committed text.** A reader of the public repository cannot open a local notes file, a plan, a task number or an agent's name; plan vocabulary ("phase 3", "per the reviewer", "v2 of the fix") reads as noise. Check: `git diff <base> | grep -nE '^\+.*(/home/|/Users/|TODO\(agent|task-?[0-9]|wave [0-9]|phase [0-9]|per the (plan|reviewer)|CLAUDE\.md)'` returns nothing in shipped code, comments or docs; each hit is replaced by the fact it pointed to; pipeline directories are excluded through `.git/info/exclude`, never a tracked `.gitignore`.
- **Read the whole final diff, and search history for anything you remove.** Merges and conflict resolution drop lines silently, and removed code may be an earlier fix for a bug that comes back. Check: `git diff <base>...HEAD` was read end to end; every removed line is explained by the change; each removed or narrowed block was looked up with `git log -S '<snippet>'` and the report notes what that history showed.

## When it does not work

- **After two failed attempts at the same fix, stop and re-diagnose.** Failed agent runs are longer and loop on variations of one idea; patching forward adds layers to the wrong design. Check: the attempt log shows no third variation of a change without new evidence; the third step is a written root-cause analysis (what the structure is, how a reference implementation does it) followed by a test, or a hand-off listing what was tried.
- **When requirements conflict, stop and report rather than pick a side quietly.** A test that contradicts the spec, a spec that contradicts the code's real interfaces, or a request with two readings all invite a workaround that satisfies the wrong party; giving agents an explicit "flag it" exit cut test cheating several-fold. Check: the report lists each conflict found and how it was raised; none was resolved by editing the test, by code that recognises test inputs, or by an unannounced reinterpretation of the spec (see `testing.md` Core).
- **Turn every correction into a rule and sweep the whole diff for the pattern.** Fixing only the instance a reviewer named leaves the siblings; one review that named 13 untranslated strings missed 60 more in the same change. Check: after each finding, `git diff <base> | grep` (and `git grep` over the codebase where relevant) for the same pattern and fix every hit; the lesson is recorded where the project keeps rules, updating a stale rule in place rather than appending a contradicting one.
- **Budget long runs and separate iteration from full sweeps.** Unbudgeted runs re-run every sweep per iteration and burn hours, and a tired loop dismisses real regressions as noise. Check: the run has a time or step budget with "stop and report a diagnosis" at the end; iterations run the targeted test only (`--tests`, `-run`, `-k`) and the full suite runs once at the end; a probe that got worse is a regression until shown otherwise.

## Parallel agents and the merge

- **Parallel agents write files; only the main session commits and merges.** Agents sharing one git index make add and commit non-atomic: an amend swallowed another agent's commit and a reset dropped a third. Check: implementer prompts forbid commits in a shared checkout; an agent that commits has its own worktree created by the orchestrator from the intended base (`git -C <worktree> merge-base --is-ancestor <base> HEAD` exits 0); merges happen one at a time.
- **Gates re-run on the merged tree, and agent claims are reproduced before they are published.** Each agent's tree was green while the merge carried a type error; reports reached correct conclusions on numbers that did not reproduce. Check: after each merge the main session runs typecheck, build and the full suite itself; a headline number or claim from an agent's report (a count, "the test deletes real files") is reproduced by a command in the main session before it enters a PR body or summary.
- **Give each agent the files it owns, and tell siblings about cross-cutting workarounds.** A workaround one agent added was invisible to a sibling whose code then broke; two agents each deleted tests as "covered by" the other's file while both were cutting it. Check: every prompt lists owned files and names files owned by others; a workaround added mid-wave is sent to every affected agent; cross-file coverage claims are checked jointly on the merged tree.
- **Confirm an isolated agent edits its own worktree.** The same relative paths exist in the main checkout, and tooling resolves modules upward into the parent, so edits and "green" builds can land in the wrong tree. Check: the agent's first command asserts `git rev-parse --show-toplevel` equals its worktree; after each agent, `git status --short` in the main checkout shows no new changes or untracked files.
- **Every agent has stopped before you commit.** An agent that already reported can still be running background work and edit files after the commit. Check: every launched agent is finished or stopped, then `git status --short` is clean apart from the intended change, immediately before the commit.
- **Isolate scratch space and dependency installs per agent.** Same-named scratch scripts overwrite each other, and a package install in one worktree that shares a dependency tree deleted packages under every other agent mid-gate. Check: each task uses its own scratch subdirectory; no `npm install`, `pip install` or equivalent runs inside a worktree with a symlinked or shared dependency directory; durable inputs live in the project's pipeline directory, not a temp dir that is cleaned overnight.
- **Snapshot before a mutation or revert check, and never undo with `git checkout <file>`.** Checking out a file reverts all of it and has wiped real uncommitted work; a shared scratch copy can be overwritten by a parallel agent. Check: the real change is committed or copied to a task-named private directory first; the pristine copy is compared with `cmp -s` against `git show HEAD:<path>` before restoring; the restore runs in a `finally` block or `trap ... EXIT`.
- **Keep heavy builds from starving the user's machine.** Several agents compiling at full priority make the user's desktop unusable. Check: heavy builds and full suites run through one shared lock at low priority (`nice -n 19 flock /tmp/<project>-build.lock <command>`); nothing an agent started is left running.
- **Keep the user's global config out of tests, and never bypass hooks.** A globally enabled setting such as commit signing breaks VCS tests, and skip flags hide real failures. Check: VCS-touching tests run with `GIT_CONFIG_GLOBAL=/dev/null` (and `GIT_CONFIG_NOSYSTEM=1`); when a hook rewrites files they are staged and the commit retried; no `--no-verify` or hook-skip variables without explicit permission for that commit.

## Hand it over

- **Hand the change to the human with one command, what to look at, and what working looks like.** The owner verifies user-facing changes personally, and a hand-off without a command and an expected result stalls. Check: the final report has one runnable command, the place to look (screen, endpoint, file) and the visible sign of success; the agent does not start an interactive session on the user's behalf.
- **Fix the run-locally script, not the invocation.** A wrapper or one-off env prefix means the next person runs a different binary, PATH or environment from the one that was tested. Check: the project's dev or run script exercises the change end to end with no extra env vars, flags or wrappers; if testing needed one, the script was changed in the diff.
- **Run CI's exact commands before calling it done.** A local build without CI's build tags, feature flags or target OS hides code that only the shipped variant compiles. Check: the commands in the CI workflow file (`.github/workflows/*.yml` and similar) were run verbatim, and every shipped variant built at least once (gate details in `testing.md` Core).
- **Re-verify after every hand edit, including the human's.** Defects that reach a published text tend to arrive after the last check: a paste duplicates a section, a block is left unclosed. Check: the cheap structural checks (build, linter, heading count, open and close pairs) ran again on the final posted version, not only on the draft.

## Verify it

Scope and leftovers:
- Files touched: `git diff --stat <base>...HEAD`; every file maps to a requirement
- Local or process references: `git diff <base> | grep -nE '^\+.*(/home/|/Users/|task-?[0-9]|wave [0-9]|phase [0-9]|per the (plan|reviewer)|CLAUDE\.md)'` returns nothing
- Removed code: `git diff <base> | grep '^-' | less`, then `git log -S '<snippet>' --oneline` for each removed block
- Old names gone: `git grep -n '<removed identifier>'` returns nothing

Prove a check can fail:
- Linter or scanner: add one known violation to a scratch copy, run the tool, confirm a non-zero exit, remove it
- File identity: `cmp -s a b; echo $?` (0 identical, 1 different), never a filtered `diff` piped to `grep`
- Null results: confirm the run executed something (test count above 0, the probe's log line present) before reporting "no hits"

Worktrees and merges:
- Right tree: `test "$(git rev-parse --show-toplevel)" = "<worktree path>" || exit 1`
- Right base: `git merge-base --is-ancestor <base> HEAD && echo ok`
- Main checkout untouched: `git -C <main checkout> status --short` is empty after each agent
- After merge: typecheck, build and full suite in the main session, exit codes recorded

Isolation:
- VCS tests: `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_NOSYSTEM=1 <test command>`
- Heavy builds: `nice -n 19 flock /tmp/<project>-build.lock <build command>`
